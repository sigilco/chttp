# Issue #14 slice: server-side component rendering (pages, SSG, ISR)

Slice of P5/M3 "component framework server side". Not the whole framework.

## Lands
- `@chttp/html` subset exports: `page(head, body)` full-document shell (`<!doctype html>` + html/head/body) and `IsrPage` — TTL-cached markup (`render` closure + `revalidateSeconds`; re-renders lazily on expiry via `Date.now()`).
- SSG pattern: render page markup once at startup, serve from a route — no new API needed; demonstrated by the example.
- `examples/pages`: tiny blog. `/` index rendered once (SSG); `/post/:slug` ISR (revalidate 5s); components as `(props) => string` fns. node:test e2e over real HTTP.
- Unit tests `packages/html/test/page.test.js`; gate `bench/apps/chttp-html.ts` exercises new exports (100% static required).
- Docs: `docs/html.md` gains a "Pages, SSG and ISR" section + honest limits; package README updated.

## Remaining surface (PR body, not this PR)
- Per-request data loading / load fns; layout nesting; streaming SSR; islands/hydration; build-time prerender + `@chttp/static` handoff; SWR background revalidate; HEAD/metadata model beyond a raw head string; JSX->h lowering in unplugin.

## Gates
`scriptc coverage bench/apps/chttp-html.ts` 100%; `pnpm --filter @chttp/html test`; `pnpm --filter chttp-example-pages test`; oxlint/oxfmt.
